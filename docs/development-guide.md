# Development guide

Install Python 3.12+, create and activate a virtual environment, and install `requirements.txt` as shown in the README. `python -m pytest -q` runs offline tests with synthetic mocked responses; they do not validate the live API. `python main.py list-sources` displays the only connector. `test-connection` performs an actual GET without saving content, while `fetch world-bank-female-labor-force` validates and stores observations.

Configuration is validated with Pydantic at startup. The connector checks its permission before retrieving, validates indicator, country, year, response completeness and values, and retains nulls. Output has retrieval time, source, indicator label, attribution and license references. A response with more than one page or mismatched totals fails rather than silently saving a partial dataset. Files are overwritten after a successful validation. `data/raw` is reserved and currently unused.

The shared HTTP client retries bounded transient transport and server errors, and stops on 429 in accordance with the source policy; it never retries before Retry-After. TLS verification is always enabled. Logging contains source, destination host, duration, status, error category and retry count; response bodies, proxy URLs and headers are not deliberately logged. The application does not configure a VPN.

Future connectors require an independently reviewed permission decision and source-specific implementation. Do not treat the base class as permission for arbitrary sources. See [source policy](source-policy.md).

## Output recovery and validation

Both JSON and JSONL are fully serialized before publication. Same-directory temporary files and copies of existing outputs are flushed and closed before sequential replacement. If a replacement fails, the connector attempts to restore already replaced files (or remove newly created files). If rollback also fails, the CLI reports that outputs may differ and retains `.world-bank-backup-json-*.tmp` and `.world-bank-backup-jsonl-*.tmp` files for manual recovery; identify each by its suffix before restoring it. Other temporary files are normally removed.

This is not a multi-file atomic transaction. Concurrent readers may see a mixed pair during replacement; concurrent writers are unsupported. A crash, power loss, forced termination, filesystem failure, or failed rollback may leave a mixed pair and recovery files. Before using outputs after such an event, inspect the pair and restore the labeled backups if needed; do not start another write until recovery is complete. Individual file fsync is used, but directory metadata durability is not guaranteed. Backup cleanup can itself fail under filesystem errors.

Indicator values must be JSON numbers (integers or floats) or null; booleans, strings, arrays, objects, NaN and infinities are rejected with zero-based record index and field context. Permission is checked at both `run` and `retrieve`, and approval is restricted to the exact built-in connector and approved endpoint. This guards the application flow, not against a person who can modify Python code.

## LoadSafetyMonitor

`market_tool.load_safety_monitor.LoadSafetyMonitor` is wired into the NiniSite collector but not the World Bank connector; callers must route every request for a site through the same monitor instance. It makes only GET requests, does not follow redirects or retry automatically, and keeps TLS verification enabled. No network requests occur when merely importing it.

Use `with LoadSafetyMonitor(delay_seconds=12, failure_threshold=2) as monitor:` and call `monitor.get(url)` only after source authorization, robots and privacy checks. The delay must be between 10 and 15 seconds and starts when the prior request finishes. A lock ensures only one call per monitor is in flight, including among threads. The default circuit breaker permanently stops that session on HTTP 429, HTTP 403, recognized CAPTCHA markup or a CAPTCHA redirect, and after two consecutive 5xx responses and/or timeouts. A successful or other non-5xx response resets the consecutive count. A first timeout is raised to the caller; there are no automatic retries. A stricter source policy takes precedence.

CAPTCHA detection covers common HTML form, input, iframe and widget markers and redirect locations, not all possible challenges; callers must stop on any other access denial or challenge they detect. The monitor cannot enforce limits on requests made outside its instance or by other processes, does not validate robots/permissions, and does not implement collection, pagination or data anonymization. Do not create parallel monitors for the same site to bypass its limit.

## Local dashboard

Run `python dashboard.py` and open `http://127.0.0.1:8765/`; `--port` selects a different local port. `python dashboard.py --demo` runs a clearly marked in-process synthetic worker without making HTTP requests. In both modes the file size cards use actual `data/raw` and `data/processed` file sizes. Run the offline UI logic test with `node tests/dashboard_frontend_test.cjs`; backend tests use pytest.

The dashboard starts idle. Its start button collects public NiniSite topics subject to robots.txt and the shared safety monitor, with at least ten seconds between requests. New filtered first pages and observed continuation pages are stored under `data/processed/ninisite/P1`, `P2`, and so on, up to 60 files per folder; existing files are not overwritten. The worker indexes existing data across raw and processed directories and checks known IDs, URLs, titles, and text before saving. Only same-topic continuation links observed in the HTML are followed, with a 20-request continuation cap. All saved pages remain marked `complete: false`: source pagination or privacy filtering may omit content. Author fields are omitted; automatic filtering cannot guarantee anonymity. The user reports owner permission for research, whose broader reuse scope has not been independently verified.

Pause is cooperative: an in-flight request can finish, but a subsequent monitored request waits at the checkpoint. The status changes from pausing to paused only when the worker reaches it. Continue is allowed only while the worker remains attached, the permission callback allows it, and the monitor has not latched a safety stop. End safely stops the worker at the next checkpoint; it cannot cancel an in-flight request. HTTP 429, 403, recognized CAPTCHA and the repeated-failure threshold latch a safety stop for the lifetime of this dashboard process; the UI cannot reset it. Do not restart to evade an access restriction. The collector's exact type and declared scope are checked by its permission guard. Collector code that bypasses shared state or monitor cannot be controlled by this dashboard. Counters and charts are in-memory session data and reset when the dashboard process exits. Polling measures actual output file sizes without returning file names or paths; UI/API events contain no post text or query strings. The worker and dashboard must run in the same process; independent CLI processes are not automatically attached.

Topic discovery and examination counters are unique per dashboard session; requests are cumulative session activity. `messages_saved` counts locally saved message blocks, not necessarily complete topics. Independent processes are not reflected in the session counters; the stored-data panel reads the files separately.

Stored topic pages remain `complete: false`; observed links and the request cap do not prove that every reply was retrieved. Topics cannot be counted as complete solely because no further anchor was seen.

Dashboard request statistics cover HTTP responses received during the current dashboard process, including redirects and error responses; transport failures with no response are excluded. P95 uses the nearest-rank method, and the median averages the two middle values for an even sample size. A 301 is reported as Redirected and is not automatically followed. A 410 is reported as Gone; the exact URL's SHA-256 digest is stored in `data/gone-url-sha256.txt` so that URL is not requested again across restarts. The list does not include URL text; removing it resets this protection.

New numbered dashboard topic files are stored in `data/processed/ninisite/P1`, `P2`, and so on, up to 60 JSONL files per folder. Older files remain in their original location and are still checked for duplicate topics. A connection error is retried automatically after 60 seconds without a fixed retry limit, while the same safety monitor remains active. Safety stops (including 403, 429, CAPTCHA, repeated timeouts or 5xx), access-policy failures, and other errors are not automatically restarted. Pausing or stopping remains available during the recovery wait. This recovery operates only while the dashboard process is running.

## Offline market-signal processing

The World Bank connector and NiniSite collector write their existing local outputs independently. Run the offline classification stage explicitly against an existing JSONL file; it never fetches a URL or changes the input:

```powershell
python main.py process-signals tests/fixtures/market-signals-synthetic.jsonl data/processed/market-signal-runs/my-new-run --reviews tests/fixtures/market-signals-synthetic-reviews.json
```

The output directory must not already exist. It contains `accepted.jsonl`, `rejected.jsonl`, `manual_review.jsonl`, and `summary.json`. Each decision stores the complete original input record, input filename and record position, plus a decision and reason. Preserve these files as potentially sensitive: existing text and provenance are not anonymized. Collectors remain independent; processing is not automatically invoked during live collection. Inputs are UTF-8 JSONL, one JSON value per nonblank line; unsupported formats must be converted separately without overwriting the original.

Homepage metadata, marketing, navigation, known collector metadata kinds, empty records, invalid provenance and reviewed duplicates are rejected. Unknown/ambiguous types and unreviewed signal types go to manual review. A separately supplied review JSON maps unique record IDs to booleans; an embedded record flag is never trusted. Only explicitly reviewed records of allowed content types pass the existing `market_signals.assess` gate. Review is an assertion about evidence, not permission, identity safety, or a validated pain point. There is no automated pain-point extraction or guarantee that a reviewer correctly classified a promotional claim. Original input text is preserved; extracted analysis must be stored separately if added later. Unrecognized legacy records without a type cannot be automatically accepted, and absent provenance must not be inferred. A failed write may leave a partial new output directory; remove it manually only after review, and choose another new directory for another run.

The synthetic example and review file are fabricated; fixture URLs point to the reserved `.example` domain and do not identify a real project. The offline report is in `reports/phase-5-offline-quality.md`.

ParsCoders has an offline parser for the observed public project-list structure in `market_tool/parscoders.py`. It extracts visible title and description excerpts only from same-host public project links, skips entries lacking links/descriptions and applies best-effort filtering. Parsed previews require individual privacy and content review. The guarded remote fetch entry point remains disabled pending source-specific automated-access and reuse approval; after a code-reviewed scope is configured, the listing preview feeds the review pipeline. There is no dashboard integration or live data collection for this source. No permission can be supplied through untrusted runtime input to override this guard.

## Stored records dashboard and continuation collection

`python dashboard.py` serves a local-only dashboard. The authenticated `/api/records` endpoint reads a bounded preview of JSONL records from `data/processed/ninisite/P*` and `data/processed/parscoders/P*`, deduplicates exact normalized visible texts, omits filesystem paths and returns 25 records per page with previous/next navigation. The dashboard displays source, best-effort filtered text and actual stored counts. Latest-batch counts are read from the saved Phase 12 continuation summary; missing statistics display as unavailable. Activity events still do not contain message text. The token protects the records endpoint; it is not an authorization to access external sources. The regex filter cannot guarantee anonymization; review before sharing.

`market_tool/ninisite_pagination.py` follows only same-host, same-topic `?page=N` links actually found in `.pagination-box`; it checks robots, uses a shared safety monitor, skips existing page numbers and checks all previously indexed text hashes, writes new numbered files without overwrite, and marks completeness as false. The observed first-page and continuation controls do not prove that all replies are accessible. Original response HTML is not archived because it can contain names, profiles and sensitive details; links and quoted blocks are excluded by the parser. Username matches are redacted without discarding an entire message, while obvious sensitive messages are omitted. Normalized exact matching can conservatively merge repeated phrases, and privacy filters do not guarantee identity removal.

The ParsCoders listing adapter is connected to the market-signal review gate, but its source-specific approval constant remains unset. It checks authorization before any HTTP request. Activating it requires a code-reviewed grant covering the exact listing and intended research use. Only listing excerpts are parsed; project-detail metadata and automatic persistence are not implemented. The contact page is `https://parscoders.com/support/contact`.
